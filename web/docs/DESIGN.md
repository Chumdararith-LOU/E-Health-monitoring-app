# Web app: HCI / UX design notes

The same principle as the mobile app: **reliable and consistent before beautiful**. The users are different, though:

| User | Context | Design response |
|---|---|---|
| **Doctor** | Short gaps between consultations, many patients, often on a clinic PC, sometimes on a phone | Dashboard that answers "who needs me today?" in one look; readable tables; a patient page with a fixed structure; works on a phone (`Web (+ mobile view)`) |
| **Admin** | Support work: wrong roles, a mistyped reading, a new field to track | Tables with search and filters; every change confirmed, reversible (Undo) and explained in plain language |

## 1. Information architecture

```
Doctor:  My patients (dashboard) → Patient → [Overview | Readings | Notes]      Settings
Admin:   Users & roles · Tracked fields · Links · Readings support              Settings
```

- At most **two levels**. Breadcrumbs show the way back.
- The **sidebar** on desktop becomes a **bottom bar** on phones, with the same items in the same order.
- Tabs, period and filters are kept in the URL (`?tab=readings&p=90`), so Back and Refresh work and a view can be bookmarked or shared.

## 2. Heuristics applied

| Principle | Where |
|---|---|
| **Visibility of system status** | KPI tiles (need attention, recorded today X of Y, out-of-range, missed days); "Today" badge per patient; counts on filter chips and tabs; "Showing 1–15 of 27"; toast after every change |
| **Match with the real world** | Clinical units on every value; "Systolic / Diastolic" as doctors expect; Khmer dates, months and optional Khmer numerals |
| **User control & freedom** | **Undo** for role change, delete, archive, link removal and admin edits; Esc closes dialogs; asks before discarding unsaved edits |
| **Consistency** | One component per concept (Button, Field, Chip, Segmented, Tabs, Badge, Modal, Toast). The primary action is always top-right in the page header or bottom-right in a dialog. Destructive actions are red and say what they do ("Delete reading") |
| **Error prevention** | Admin cannot change their own role; a field's unit and number type are locked once it has data (old values stay correct); fields are *archived*, not deleted; same safe limits as the mobile form |
| **Recognition rather than recall** | Sortable column headers show the sort direction; the reading detail shows each value next to its normal range (it explains *why* it is flagged); a live preview of a new field as it will look in the mobile form |
| **Flexibility & efficiency** | Search and filters on every list; keyboard use everywhere: Tab, arrow keys in tabs, segmented controls and charts, Enter to open |
| **Minimalist design** | Neutral surfaces. Colour is reserved for the one action colour and for health status |
| **Help with errors** | Messages say what to do ("Enter a number from 50 to 260"), sit next to the field, are linked with `aria-describedby`, and focus moves to the first wrong field. A summary banner appears at the top of the form |

## 3. Doctor dashboard (FR-12)

- **Sort by need, not alphabetically.** "Need attention" means the latest reading is out of range, OR there were 3 or more out-of-range readings in 7 days, OR 2 or more missed days. The rule is written under the table, so it is never a black box.
- Each row shows the **Today** status, the **latest reading** (values out of range have an arrow and colour), the **7-day average**, a **14-day systolic sparkline** and **flag badges**.
- Each row has a real link (keyboard users can reach it), and clicking anywhere on the row also opens the patient.

## 4. Patient page (FR-10, FR-11, FR-17, US-19)

- **Overview:** period (7/30/90/custom, with native date pickers) → summary table (min / average / max / count) → latest reading + 7-day dots → one chart per measure.
- **Charts:** one y-axis each; normal range as a grey band; 2 px lines; a legend for 2 series. The hover or keyboard crosshair shows a tooltip, and Enter or click opens the reading. Each chart has a **Table** view (accessibility, and exact values).
- **Readings:** paged table with an "Only out of range" filter; columns for admin-defined fields appear automatically.
- **Notes:** the doctor's notes, clearly marked "Visible to the patient and caretaker".
- **Export PDF:** a print stylesheet hides the navigation and controls and adds a report header (patient, period, generated by, date).

## 5. Accessibility (WCAG 2.2 AA target)

- Contrast is 4.5:1 or more for text, and targets are at least 44 × 44 px (2.75 rem).
- Focus is always visible (3 px ring). A **Skip to main content** link is provided, and focus moves to the page heading after navigation.
- Semantic HTML: real `<table>`, `<th scope>`, `aria-sort`, `<label for>`, `role="tablist"/"radiogroup"`, native `<dialog>` (focus trap + Esc).
- Status is **never colour alone**: an icon + a word + colour; out-of-range values also carry a screen-reader-only word.
- Text size setting (100 / 115 / 130 %); every size is in `rem`, so the whole layout scales.
- `<html lang>` follows the language. Khmer text gets a taller line height (1.65), and the browser picks Noto Sans Khmer glyph by glyph.
